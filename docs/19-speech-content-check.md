# 0.2.0：漏读检查与断句复查

旧版本只验证配音文件是否完整、时长能否放进时间线，没有检查实际说出了什么。`test1-0.1.8验证` 的 366 段缓存中，发现 28 段几乎只有底噪；部分有声音的文件仍漏掉了前半句或后半句。约 7:35 的“连接这两个点，就能得到整条直线”在原始合成文件中就只剩后半句，问题发生在生成阶段。

## 现在的处理方式

- GPT-SoVITS 按完整语义单位生成，使用 `cut0` 避免再次按逗号切碎。
- 检测有效 PCM 音频的响度与活动区间，排除非零底噪造成的假成功。
- 配置了本地 Whisper 模型时，复用一个离线识别实例回听配音，检查明显的开头、结尾与大段漏读。只将课程文字发给用户配置的翻译 API，配音回听不上传音频。
- 检测到静音或疑似漏读时，最多自动尝试五次，改变生成随机种子，末两次切换串行推理。重试仍失败的片段不混入成品，配音页显示具体句子、时间、应读文字和回听结果；再次生成会保留已通过缓存并使用新的种子。
- 重试时可从同一声音的已验证配音中选择一段目标语言上下文，解决很短的跨语言问句反复生成底噪的问题；候选须有当前输入指纹、完整本地回听记录、至少 90% 的匹配覆盖、3–10 秒时长及有效文件哈希。不会使用另一位说话人的片段。整课处理会在其他句子完成后，自动为剩余异常再做一轮有限重试，短句位于课程开头也能得到上下文。
- 旧项目首次生成配音或导出译声时也会检查旧缓存。没有本地识别模型时仍检查静音；不会自动下载模型，也不声称已检查漏读。
- AI 整理分句后，另以相邻语句和跨批次上下文复查误加句号造成的语法断点。每项修复须引用原文片段并说明缺少的语法成分，只允许合并同一说话人的相邻单位，完整原文及公式、讲义来源保留。
- 长字幕优先在标点、分句位置换字幕，减少按固定字数切断词组。
- 翻译时提供原句时长，要求口语读法简洁完整，不能按字数强行截断。默认“自动”会逐句选择自然速度、停顿分配及必要的局部加速，1.50 倍是上限，并非固定播放速度；可在高级设置降低上限。自动草稿的不同工作进程会保留同一时长限制。

## 使用

在“03 配音”点击“自动生成并匹配配音”。进度会显示回听检查及自动重试。问题清单中的静音、漏读项可定位到原句；再次点击同一个生成按钮即可继续，不需要逐句修改译文。

检查是质量筛查，不能保证识别每一个错字、专有名词或数学读法；音色和自然度仍应抽查。没有通过的配音不会被当成完整译声导出。测试副本与旧结果分开保存，以便对照。

## 验证范围

250 项自动测试通过，涵盖缓存失效、非零底噪、明显的开头和结尾漏读、数学数字、跨批次边界、不同说话人隔离、重试与文件完整性，以及处理流程中的时长参数传递。

真实本地 GPT-SoVITS 与 Whisper 另验证了短问句、生物、历史、物理、数学、否定条件及英文共 7 个独立文本案例；它们使用同一适配器，没有课程专用规则。原课程副本保留 4,986 个原文词，修复 3 个语法断点后为 363 个单位，均通过本地回听筛查并完成时间线混音。筛查通过不等于每一个读音已获人工确认。
