# AI API、公式准确性与成本控制

## 1. 对用户追加要求的落实

允许外部模型API，并将它作为推荐混合模式的语义引擎。桌面仍在本地；无需自建云端平台。首先直接接模型API，配合固定流水线，而不是为首版引入复杂的自治agent框架。

运行时的“数学解析、术语翻译、讲义整理、质量复核”是有输入输出边界的模型任务。程序负责取证、重试、时序与导出，模型不能任意调用shell或浏览用户文件。开发阶段的4个协作agent与应用运行时的模型任务是两回事。

## 2. DeepSeek 名称、能力与价格核查

2026-10-18核查官方中文文档：建议调用名为 **`deepseek-flash`**；旧名 `deepseek-v4-flash` 仍接受，但实际转到当前V4.1 Flash服务。产品配置记录请求名、返回模型标识和核查日期，不把别名当不可变模型版本。[官方模型与价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)

官方表列Flash支持JSON输出、工具调用与图像理解；因此可考虑直接让它结合转写与公式裁剪解析，而不必默认再购买独立视觉API。是否能正确识别本课程手写和数学歧义仍需实测。[图像输入文档](https://api-docs.deepseek.com/guides/vision/)

人民币/百万tokens的核查快照：

| Flash计费项 | 空闲 | 高峰 |
|---|---:|---:|
| 输入，缓存命中 | ¥0.02 | ¥0.04 |
| 输入，缓存未命中 | ¥1 | ¥2 |
| 输出 | ¥4 | ¥8 |

价格、服务版本和时段规则可能变化，发布时更新配置，不写死在UI或按固定小时视频收费。[官方计费规则](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)

思考模式需要显式配置，不能依赖默认值；只对高风险公式启用受控推理，普通批量翻译先测试非思考模式。用最终JSON内容作为产物，思考输出不进入讲义或常规日志，实际usage用于记账。[官方思考参数](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)

## 3. 路由策略

| 场景 | 首次处理 | 失败/疑难升级 | 最终规则 |
|---|---|---|---|
| 明确简单口语公式 | 本地规则生成候选，Flash结合上下文确认结构 | 有歧义时取视觉/相邻句 | 高风险不能仅凭模型自报分数放行 |
| 普通课程翻译 | Flash，已锁定词表+前后少量上下文 | 结构检查失败仅自动修复1次 | 已人工修改内容不被覆盖 |
| 模糊公式或否定/量词 | 证据裁剪+Flash思考模式，返回候选及理由标签 | 重新取帧/回听，必要时用户选择的更强provider复核1次 | 仍不确定就待确认，不无限agent循环 |
| 清晰画面公式 | 本地Pix2Text | 用户已允许图片API时发局部裁剪 | 保存原截图和候选，不直接替换原视频画面 |
| 潦草手写或遮挡 | 标待确认，尝试附近稳定帧 | 同上；用户可手动框选/输入LaTeX | 看不清就保留原图 |
| 讲义 | 已确认证据表→Flash结构化整理 | 无来源陈述退回删除/重写 | 不联网补知识、不自动造证明 |

不默认每段都调用第二个模型，不默认多模型投票。更强模型可减少部分错误但仍不是事实裁判；升级应由测试数据证明质量提升后启用。ASR证据本身缺失时优先补证据，不能只让更大语言模型猜。

## 4. 数学解析任务契约

输入只含必要内容：段ID、原始听写、前后文、课程词表、已有关联公式、可选裁剪（用户允许时）。不要发送全片和不相关截图。

```json
{
  "segment_id": "seg-19",
  "source_text": "one over x plus one",
  "source_language": "en",
  "target_language": "zh-CN",
  "context": "暂无可确定分母范围的前后文",
  "allowed_evidence_ids": ["ev-a19"],
  "image_evidence_ids": []
}
```

期望结构化响应（下例是设计样例）：

```json
{
  "segment_id": "seg-19",
  "candidates": [
    {"latex": "\\frac{1}{x}+1", "spoken_target": "x分之一，再加一"},
    {"latex": "\\frac{1}{x+1}", "spoken_target": "x加一的和的倒数"}
  ],
  "selected_index": null,
  "review_required": true,
  "reason_codes": ["AMBIGUOUS_DENOMINATOR"],
  "evidence_ids": ["ev-a19"]
}
```

本地验证：允许字段/ID、LaTeX可渲染、变量/数字/符号差异、候选是否有依据、无凭空补函数/边界。需要确认时把候选存进原始模型产物，核心Formula的 `latex` 可以为null，界面要求人工选择或保留来源。

API JSON模式只保证尽量输出指定结构，不能假设服务端严格执行本项目Schema；本地仍逐项验证。请求中禁止擅自补全数学条件，允许明确“不确定”。提示词的确定语气不是验收指标。

## 5. 成本和重试预算

总文本费用按 `未命中输入tokens×单价 + 命中输入tokens×单价 + 实际输出tokens×单价` 汇总；图像token与思考输出按API实际usage纳入，不能只数最终译文。参考音色/TTS若走另一API单独记账，不能包含在DeepSeek文本费用里。

示例：假设某次任务所有文本调用合计50,000个未命中输入、5,000个命中输入、20,000个输出tokens，按上表空闲价计算为 **¥0.1301**。这是算术示例，不是一小时课程报价；多轮上下文、图像、重试、思考和讲义长度都会改变实际量。没有真实视频和usage前不承诺单课费用。

应用提供用户自设课程预算和调用上限。启动先对样本估算token，再给区间；运行时保留每阶段实耗。每次调用前预留按允许最大输出计算的预算，多并发共享额度；不依赖已产生费用才停止，仍标明这不是供应商账单的绝对硬上限。

固定系统提示和术语前缀有利于服务端缓存；跨请求复用是否命中以返回usage为准。本地缓存确保用户反复试听、改字幕样式不会重复付费。术语或读法变化只重跑依赖段。不为了缓存率无意义上传整课。

429/暂时5xx按有限次数退避重试（最多2次传输重试），结构错误最多1次修复，不做无限循环。超时响应可能已经计费，记录不确定请求，重试前说明这一点；优先采用provider提供的幂等机制，未提供则不能声称exactly-once计费。达到预算/调用上限时保存结果、停止新请求，等待用户提高预算或改本地模式。

## 6. 数据去向与版本变化

首次配置API时保存“允许发文本”和“允许发公式截图”的独立选项；音色API另外列出参考音频与目标读法。混合模式先检查Key、余额/权限错误、目标模型能力，真实处理前不向服务发送测试课程材料。

每次保存provider变化、请求模型名、返回模型标识、参数、提示版本、usage和处理日期，不记录密钥。模型别名可能升级，缓存与回归至少以返回模型标识和已知服务版本分区；若供应商只返回别名且无不可变版本，按日期/能力探测进行保守失效，不能保证跨天逐字复现。重新处理已确认公式前要保留旧revision。

此设计阶段只核查文档，未调用付费API、未上传课程资料、未进行模型准确率或费用实测。具体门槛见 [验收标准](05-acceptance.md)。
